## TL;DR

Added NOOA v2 modules (two-tier memory + supervisor hysteresis 15/20/3). 536 events mention NOOA. LB 1.51, -1.05 from V24's 2.56. Modules ran but regressed LB.

## Context

V31 attempted to add 7 NOOA modules on top of V24, but the wiring was broken (AttributeError on `_system_prompt`). V32 fixed the wiring and verified NOOA events fired (469 events). V33 was the first LB submission with NOOA modules actually executing.

NOOA v2 architecture:
- M1. NOOAMemory: two-tier (intra-game + cross-game), append-only
- M3. NOOASupervisor: hysteresis (15min/20cooldown/3max-switches)

The hypothesis: cross-game memory would let the solver transfer learnings from one game to the next, improving LB on the 110 hidden games.

## Technical Choice

NOOA v2 modules installed via a cell that overrides `solver.analyzer_factory` to wrap `ToolAgent` with NOOA hooks. The modules persist state to `/kaggle/working/nooa_memory.json` between games.

The supervisor uses hysteresis: 15 minutes per strategy, 20-minute cooldown, max 3 switches per game. This prevents rapid strategy oscillation.

## Outcome Analysis

LB 1.51, -1.05 from V24's 2.56. NOOA modules ran (536 events mention NOOA) but regressed LB.

The NOOA modules added overhead: each action now goes through NOOAMemory (read + write) and NOOASupervisor (strategy check). This overhead reduces the number of actions per game within the 9-hour budget.

The cross-game memory did not help. The 110 hidden games are diverse; learnings from one game do not transfer to another. The supervisor's strategy switching added noise without improving outcomes.

This is the second confirmation (after V25's grafts) that adding modules to V24 regresses LB. The pattern: V24's config is a local optimum; any addition breaks it.
