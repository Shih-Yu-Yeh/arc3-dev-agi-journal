## TL;DR

Fork dvm 的 kernel 觀察 vLLM 啟動處理。LB 0.80，比 V13 -0.07。沒加新 patch，純觀察。

## Context

V14 的靜默失敗凸顯我對 TAAF setup command 流程理解不夠。與其再 push 一個壞 patch，不如 fork `dvm` 的公開 kernel 觀察另一隊怎麼處理 vLLM 啟動、env var 順序、bundle 解析。

目標不是改善 LB，而是學 Tufa 文件沒寫的實作細節。

## 技術選擇

直接 fork dvm 的 kernel。無修改。Fork 跑 dvm 的 config 端到端。

有趣的觀察：dvm 的 kernel 用不同的 env var 注入點。Tufa stock bundle 在 setup command heredoc 內設 `LOCAL_ANALYZER_TEMPERATURE`，dvm 在 heredoc 開始前設。這正是造成 V14 靜默失敗的 bug。

## 結果分析

LB 0.80，比 V13 的 0.87 -0.07。在 hidden rerun variance 內，等同 V13。

V15 的價值不在 LB 分數，而在學到的實作 pattern：

Env var 注入點很重要。Tufa stock bundle 在 setup command heredoc 內讀 env var，heredoc 開始後設的 env var 都太晚。dvm 的 kernel 在 heredoc 之前設，讓 setup command 能讀到。

這解釋了 V14 的失敗：temperature patch 在 heredoc 開始後才設 env var。Setup command 擷取預設 0.6 寫進 `taaf_setup_env.json`。Solver 從未看到 temperature 0.3。

未來版本的修法：在 Cell 5 (TAAF setup command 在 Cell 6 跑之前) 設 env var，不是在 Cell 6 內設。
